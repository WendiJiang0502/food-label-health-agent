# ADR-010 商品需求解析、字段证据与场景评测

日期：2026-10-03。状态：正式服务已启用。扩展 ADR-009。

## 需求进入比较流程

页面和聊天的 retrieval_query 经过同一个明确规则解析器，输出场景、食用方式、营养目标、比较方向、比较基准、原文片段及需澄清事项。当前支持糖、钠、蛋白质、脂肪、饱和脂肪、膳食纤维和能量的明确中文表达。解析器是可审查的规则实现，尚未使用模型提取任意自然语言约束。

“糖更少”要求候选低于当前商品；“低糖”仅作为同口径候选间的排序偏好，不构成低糖营养声称。“能直接吃”需要具体商品名称中有即食依据，不能用笼统类别用途推断。早餐场景仍用于召回，不构成营养适宜性结论。新过敏/禁忌、无糖声称、数值边界及冲突方向返回澄清提示，不修改个人设置。

查询沿 HTTP/聊天 → 工作流 → MCP 复核工具传递。程序先保留原有过敏与证据门禁，再检查查询目标。缺当前数值、缺候选数值、计量口径不同、来源冲突、未改善或即食依据不足时，候选不进入本次匹配列表，并携带原因。可确认份量换算至每100克/毫升；质量和体积之间不猜密度换算。明确查询排序方向可覆盖相反的软排序偏好，但不能覆盖硬性限制。

## 字段证据

统一记录：字段名称、值、单位、计量基准、来源 URL、来源版本、原文片段、记录时间、证据 ID 和审核状态。目录资料继承现有严格包装/营养字段复核结果，未达到该条件仍标为目录转录；API 保持未复核，OCR 保持草稿。

外部观察保存在 SQLite field_observations，商品 ID 与证据 ID 组成唯一键。来源更新保留历史记录，当前版本与历史版本分开，不能把旧配方和新配方直接当作同时存在的来源冲突。比较当前 API 与当前 OCR 的同字段、同单位、同口径值；发现差异时保留双方并标记待复核，不选择一个覆盖另一个。未知计量口径单独标识，不强行比较。配料文本差异是复核线索，不等于已证实配方错误。

字段冲突及缺少的营养、食用方式依据进入需求补齐队列；字段更新后清理已不存在的冲突标记。仍由现有月度服务处理，不在每次搜索时重复抓取。外部商品不会因字段齐备而自动晋升推荐。

页面同时展示“本次需求核对”和可展开的逐项来源；聊天返回 search_intent、intent_match、field_evidence。比较失败时需要说明缺什么，不得声称需求已满足。
