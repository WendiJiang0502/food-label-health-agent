# ADR-001：Agent 状态协议与安全路由

状态：Accepted
日期：2026-08-02

## 背景

食品标签 Agent 同时包含 OCR、配料解释、法规检索、用户约束和替代品推荐。若让语言模型自由选择步骤，可能在图片模糊、过敏原信息缺失或法规检索失败时直接给出看似完整的结论。

## 决策

采用显式状态机，并将以下信息作为一等状态：

- 原始输入与字段级 OCR 置信度；
- 用户已经确认的标签字段；
- 用户硬约束及严重程度；
- 结构化风险结论；
- 法规证据的版本与适用日期；
- 未知项、警告、错误和审计事件；
- 当前阶段与下一条允许的路由。

节点只返回状态增量，不在节点间传递隐式全局变量。路由函数保持纯函数，便于单元测试和审计。

## 三层职责

1. **MCP 工具层**返回结构化事实、证据和来源信息；
2. **LangGraph 编排层**执行必经节点、暂停、恢复和安全门；
3. **LLM 解释层**组织语言，但不能修改规则引擎的风险等级。

## 安全不变量

1. 缺少配料表或配料字段低于置信度阈值时，路由到人工确认；
2. `avoid` 风险必须进入最终警告，不得被后续节点覆盖；
3. 没有识别出风险不等于证明安全；
4. 缺少适用法规证据时，法规性结论必须降级为未知；
5. 替代品必须重新执行相同的安全规则；
6. 每个高风险判断必须记录工具、规则和知识快照版本。

## 为什么核心协议不直接依赖框架

状态类型、枚举和路由规则使用 Python 标准库实现，LangGraph 只负责适配和运行。这样可以：

- 在没有网络和第三方依赖时运行安全测试；
- 避免业务规则被框架升级绑死；
- 让 MCP、批处理和 API 使用同一套领域协议；
- 将来更换编排框架时保留测试资产。

## 后果

优点是行为可审计、可恢复、可测试。代价是状态模型和节点契约需要严格维护，新增字段要考虑向后兼容和审计迁移。
