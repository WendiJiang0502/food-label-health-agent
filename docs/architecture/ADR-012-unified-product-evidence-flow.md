# ADR-012：统一替代品入口、商品证据投影与补齐回流

日期：2026-10-05
状态：代码实现、回归及正式资料隔离验证完成；尚未重启正式服务。

## 问题与结果

原来网页在工作流之外追加官网初筛和缺口记录，对话只取得工作流结果；商品 RAG 没有官网发现资料；官网补齐任务也没有后台对账消费者。

现在网页和对话都通过 `run_alternative_workflow` 调用 `AlternativeEvidenceService`：读取同一批来源资料、更新证据投影、执行原有图工作流、初筛、记录缺口。对话与网页共享同一个服务实例。对话只从 `eligible` 选择推荐，官网初筛的 `matched` 不能作为审核通过的证明。底层 MCP 查找/复核/比较工具仍保留各自单一职责，不伪装成完整用户工作流；其商品检索读取同一个知识库。

## 数据契约

采用兼容投影，不破坏既有正式目录、OFF 原始资料、图片证据文件。所有商品检索文档提供版本化的 `evidence`，包含身份、来源版本、时间、证据层级、字段观察和审核信息。官网字段也复用既有 `observation` / `summarize_fields` 契约，保留字段值、单位、计量口径、原文、来源、版本和证据 ID。

官网初筛、补齐对账使用同一个营养解析函数；官网检索与初筛使用同一个证据生成器和有效期判断。原有不同来源的审核政策不被抹平：官网字段仍是未审核来源证据，包装审核与用户约束复核仍单独执行。

不按同名自动合并商品；缺失条码、SKU、规格仍为空。`official_evidence` 是可重建的 SQLite 投影，不是新的权威主数据。全量替换在事务内完成，被拒绝、移除、批准进入正式目录的候选退出这个未审核投影。单次图执行通过有清理保证的上下文保存来源快照，避免并发请求在检索与初筛之间使用不同批资料。

## 补齐回流

流程：查询产生缺口 → 去重记录需求 → 月度来源刷新或人工资料更新 → 后台本地对账 → 更新检索投影及任务状态 → 下一次查询重新筛选。

后台每次运行都执行本地对账，不增加网络抓取频率；外部来源仍按既有月度安排刷新。网页手动刷新/审核后立即同步，下一次搜索也会同步，因此不需要等待下个月才能使用新资料。

任务状态：

- `needs_label` / `needs_review`：等待标签或审核。
- `not_declared`：当前版本完整标签已审核但未声明，不允许同版本重试。
- `source_available`：来源已提供对应字段；不等于包装审核或符合个人约束。
- `resolved`：已批准的正式包装记录解决包装审核任务。
- `rejected` / `source_missing`：来源拒绝或消失，不能继续使用旧完成状态。

字段删除、来源变化、证据过期会重新打开任务。状态转换写入 `official_completion_transitions`；重复对账不重复写转换。需求日志仍只保留去重哈希与泛化字段，不保存用户原话或过敏项目。

官网任务不会误入仅能处理 OFF 条码的补齐队列。没有自动下载适配器的来源仍等待资料输入；对账不会凭空补出糖含量，也不会重复请求同一页面来假装补齐。

## 边界

本次是连接可靠性改造，不是商品准确率评测，也没有新增真实糖数据。原始资料的真实性、缺失包装、未支持来源的适配、实际用户评测仍需各自证据。会话持久化启动问题不在本次修改范围；正式上线前应考虑当前内存会话在重启时的丢失问题。
