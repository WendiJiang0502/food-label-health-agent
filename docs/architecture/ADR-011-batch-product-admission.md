# ADR-011 批量身份、分用途准入与异常复核

日期：2026-10-03。状态：正式启用。

## 处理链路

已有 OFF 候选 → 身份档案与版本留存 → 月度详情补齐/腾讯 OCR → 字段证据与冲突 → 分用途能力 → 异常批次。商品身份记录校验条形码、品牌、完整商品名称（含口味线索）、规格和导入地区。常见 kg/g、L/ml 规格统一，不能把质量与体积视为同一规格。当前来源仍为 OFF；没有新增官方数据供应商，也不跨不确定身份自动合并资料。

`BatchKnowledge.assess_all()` 记录当前身份版本和评估报告。来源内容或 OCR 草稿变化使复核版本失效；同一条码的历史身份差异需重新核对。商品能力附在商品 RAG 的 admission 字段，不授予最终推荐资格。

## 能力边界

- searchable：有可识别名称，可作为来源线索。
- source_numeric_fields：身份字段齐备、来源近期查询、单位/基准明确、当前没有该字段冲突，仅可查看来源数值。
- nutrition_comparison_fields：当前身份与对应字段经过明确人工采用；仍非医学/过敏安全结论。
- ingredient_judgment：当前身份与配料文字已采用。整份包装完整性和高风险限制仍由现有严格门禁处理。
- strict_restriction_judgment、recommendation_eligible：外部批次始终不自动授予。这一模块不绕过现有目录复核。

当前全部外部资料来自社区 API/OCR，没有可直接满足严格来源准入的官方结构化供应商。因此不能把 54 个来源数值可用商品宣称为 54 个新增可靠推荐。

## 复核工作台

入口 `/knowledge-review`，API `/api/v1/alternatives/batch`。按类别、问题、名称或条码筛选，每页50件。逐字段并列展示 API/OCR 原文与包装图片，可先预选本页唯一、无冲突、身份齐备的依据，再由复核人提交采用、稍后或月度重试。预选不写入、不默认采用证据。冲突或身份变化只能逐条采用。

复核绑定商品、数据版本、字段与证据 ID；完整批次校验后事务写入，任一版本过期则整批拒绝（409），可重新加载。保留复核人标识、备注和时间；页面不保存管理员令牌。复核人标识是审计声明，不是额外身份认证。

权限沿用 `FOOD_LABEL_DISCOVERY_ADMIN_TOKEN`；生产环境未配置时拒绝访问 API，本地未配置时沿用本机工具访问。写入要求 JSON，同源检查阻止跨站页面提交。不要将无令牌本地模式直接公开部署。

## 自动补齐

月度服务结束后执行批量评估。OCR 按图片版本记尝试次数、失败类型、时间、下次可尝试时间。暂时失败最多自动尝试3次，图像质量或无法提取目标字段的失败等待版本改变或人工重试。重试请求加入月度队列，不触发请求内网络抓取。

同一版本 URL 的已识别文字缓存复用；缓存只保存文本和图片摘要，不保存原图。当前 OFF 图片 URL 包含选择版本，沿用该来源的版本语义；新来源不能未经验证直接复用这一策略。缓存仍是草稿，源数据变化可能形成冲突而非自动覆盖。
