# 腾讯云 OCR 食品标签评测记录（2026-08-05）

## 结论

腾讯云通用高精度 OCR 已可作为中国版的主识别服务，但当前只能用于“识别后人工确认”的证据采集，不可直接驱动过敏原或健康结论。

本轮使用 17 张私有食品标签图片。图片、文件名、腾讯原始响应与逐图结果均只保存在本机，不进入 Git。匿名汇总如下：

- API 成功率：17/17；
- 平均云端识别耗时：1.111 秒；
- 中位云端识别耗时：0.974 秒；
- 代表性高难样本离线重放：7 张；
- 结构完整：2 张；
- 被证据安全门拦截并要求人工核对：5 张；
- 不完整营养表被错误放行：0 张。

## 本轮改进

1. 配料提取从“相信 API 返回顺序”改为“使用文字框二维坐标恢复区域”。多栏标签、错序返回和褶皱标签不再把品牌、经销商、生产信息当作配料。
2. 支持标题与首行粘连、标题轻度漏字、同行碎片、跨行配料和并排元数据栏。
3. 营养表使用营养素、单位类型、行序与坐标共同配对；同一数值不能重复分配，毫克不能分配给以克计的营养素。
4. 支持同一行的中英双语营养值，以及被 OCR 拆成“389”与“mg”的数值单位。
5. 腾讯表格 API 资源包不可用时自动降级到通用高精度 OCR 的坐标表格，不让整次识别失败。
6. 配料末尾分隔符、残缺单字、括号不平衡、字段越界，以及核心营养素缺失均成为阻断问题。

## 验收边界

当前版本达到“辅助识别可接受”，未达到“无人审核自动解释可接受”。产品必须遵守以下门槛：

- 配料字段始终需要用户确认；
- 能量、蛋白质、脂肪、碳水化合物、钠任一缺失或单位错误时，不得进入自动营养解释；
- OCR 错字不得由 LLM 静默修复；候选纠错只能作为建议并保留原始证据；
- 过敏原判断只使用用户确认后的配料与独立规则引擎；
- 图片质量差、日文或复杂多栏版面可以退回手工输入，不以覆盖率换取安全性。

## 已知限制

- 褶皱、反光和极小字号仍会产生字符错误；例如单个添加剂名称可能被拆行或误字。
- 通用 OCR 可能漏掉营养素标签或单位，因此部分表格只能恢复为候选字段。
- 腾讯表格 V3 的当前账户资源包不可用；平台已降级，后续可在资源可用后重新做 A/B 测试。
- 目前只有少量图片具备人工真值，不能把 OCR 自报置信度称为真实准确率。下一轮应扩充经过人工标注的测试集，再报告 CER、配料 token recall 与营养素—数值对齐准确率。

## 可复现方式

私有腾讯原始文字框可通过以下命令离线重放，不会再次上传图片：

```bash
python -m food_label_agent.evaluation.tencent_replay PRIVATE_RAW_LINES.json \
  --output /private/tmp/tencent_replay.json
```

重放工具只处理文字与归一化坐标；输出仍应放在 Git 仓库之外。
