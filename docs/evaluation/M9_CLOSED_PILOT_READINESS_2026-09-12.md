# M9 封闭试用就绪评测 — 2026-09-12

## 结论

M9 工程实现已达到“可开始封闭试用”，但不能标记为“真人试用结果已验证”。系统门禁和真人结果门禁被有意拆开；当前唯一合法的真人状态是 `human_closed_pilot_not_run`。

## 已完成的工程闭环

- 112 个固定多轮对话案例，安全指标由程序规则判定。
- 回答级有帮助/需改进、六类原因、重试和对照包装纠错入口。
- 反馈表不保存对话或标签原文，使用哈希键并默认保留 30 天。
- 每次回答 0.25 美元默认硬预算，可由环境变量调整。
- SQLite 在线备份和 `PRAGMA integrity_check` 校验命令。
- 12 项真人任务目录及带证据类型和审核声明的结果模板。
- 8000 页面桌面与 390×844 移动视口端到端验证：评价、刷新恢复、重试、隐私提示、无横向溢出及无控制台错误均通过。
- 全量代码回归 590/590、总覆盖率 82.79%（门槛 70%）；Ruff、mypy、JavaScript 语法和补丁空白检查通过。覆盖率运行报告 5 个既有 SQLite `ResourceWarning`，不影响通过状态但仍应在后续清理。Bandit 扫描为 0 高危、7 中危、13 低危；中低项主要是 URL 打开审计、固定临时报告路径及断言使用，不能表述为零风险。
- `pip` 升级至 26.2.1、`pypdf` 升级至 6.18.1 后，`pip-audit` 未发现已知依赖漏洞；项目自身不是 PyPI 包，因此按工具说明跳过自身索引查询。
- 本机没有 Docker 命令，生产 Compose 构建与容器启动未在此环境执行，不能标记为已验证。

## 自动化和模型验证

- 离线对话评测：112/112，通过；严重风险降级、未确认事实泄漏、越权工具、提示词注入突破、工具失败后编造均为 0；急救召回 100%。
- 本轮第一次 Terra 全集运行：111/112；唯一失败是矛盾纠正案例把安全的 `language_corrected` 边界误判为必须 `standard`。修正契约后该精确案例复跑 1/1 通过。
- 第二次 Terra 全集运行：111/112；18 个远程案例全部完成，硬安全指标全部通过，证据一致率 98.48%。唯一失败同样是安全后处理正确触发 `language_corrected`，而多轮指代场景只接受 `standard`。该场景接受两种安全边界后精确复跑 1/1 通过；完整响应 3912 ms、首 token 652 ms、估算成本 0.003484 美元。
- 第二次全集性能观测：平均完整响应 4091.85 ms、P95 7312.64 ms、首 token 平均 966.75 ms、估算总成本 0.066704 美元。P95 仍高于 M9 真人试用目标 7000 ms，因此实际试用必须继续观测，不能预先宣称达到延迟门槛。

## OCR 证据状态

9 张真实包装图的冻结开发集历史运行结果为：API 9/9、关键事实召回 92.67%、过敏原召回 100%、数值 token 与营养素—数值对齐均为 97.14%。这些样本参与过调优且只有单人复核，不能作为独立发布集。正式 OCR 门禁仍要求至少 50 个真实样本和 30 个双人盲审金标。

本轮没有重新把这 9 张私有图片发送给腾讯云：该动作需要图片所有者明确授权。代码回归覆盖了多行过敏原、营养表局部重试、720p 质量判断、人工确认和评测门禁，但当前云端重跑状态必须保留为“未授权，未执行”。

## 与全项目公开发布的区别

统一 `release` profile 仍然会失败，这是预期且不能通过降低门槛消除。除本页的真人试用与 OCR 证据外，当前还缺生产替代品目录的品牌/配方/实物背标覆盖，以及实际部署环境中的 HTTPS 域名、持久卷、站点与管理员令牌、隐私政策、服务条款、法律审查和处理方协议。M9 的“可开始封闭试用”不等于全项目可公开多用户发布。
