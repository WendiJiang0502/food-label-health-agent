# 大陆条码接口小样本补齐测试

2026-10-04，状态：凭据已验证，首轮18个商品真实查询完成。结果见 `artifacts/domestic-pilot/live-2026-10-04/report.md`，原24条准备样本保持不变。

## 样本与对照

固定样本见 `artifacts/domestic-pilot/sample.json`。来自现有122个中国标签范围的OFF候选，剔除校验不通过的条码，按类别抽取早餐谷物、乳制品、饮品各8个，共24个。优先缺身份字段，保留对照，实际15个身份缺口样本、9个身份较完整对照。此样本不能代表大陆零售市场覆盖率；条码前缀不作为生产国依据。

只读正式数据库，保留名称、品牌、规格、配料和糖数据的基线及版本。不能修改基线迁就供应商结果。报告和供应商允许保留的字段独立保存，不写入正式候选、不执行人工复核、不下载或OCR图片。

## 首个供应商

ShowAPI 商品条码查询 66-22。公开文档：
- https://www.showapi.com/guides/barcode-quickstart-66
- https://www.showapi.com/guides/barcode-response-fields-66

此次只实现此接口的明确字段契约；没有假装接入聚合数据、京东或 GS1。先取得可测试的商品查询权限，确认调用额度和缓存/展示授权。不要因为存在商品图片字段就推断有包装背标、完整配料或营养表。

本地配置文件 `~/.config/food-label-agent/.env` 增加 `FOOD_LABEL_SHOWAPI_APPKEY`，值为已开通66-22权限的AppKey。密钥不要放入聊天、仓库或报告。本轮已从本地配置读取凭据并成功调用；报告不包含密钥。

运行（有凭据时才加 --run）：

```sh
set -a
source "$HOME/.config/food-label-agent/.env"
set +a
PYTHONPATH=src .venv/bin/python -m food_label_agent.evaluation.domestic_pilot --run
```

默认只准备样本，不访问供应商；既有 sample.json 固定复用。显式 --run 最多30条、当前24条、串行间隔1秒、无自动重试，服务级鉴权错误停止余下批次。重复执行 --run 会再次调用供应商，应先检查报告。

## 指标与判定

- 条码匹配率：供应商明确成功且回显条码通过校验并一致；无回显不能记为匹配。
- 提议补齐商品数：基线缺字段、新来源提供值；仍需核对SKU、口味和包装。
- 身份差异：已有名称/品牌/规格与新来源不同，保留差异，不直接覆盖。
- 图片可用性：统计HTTP及HTTPS图片线索数量，可用链接列表只保留HTTPS；未下载图片，是否为可读背标待另行验证。
- 配料/营养补齐：该公开契约不保证这些字段，报告为未评估；不能据此声称改善了营养比较能力。
- 新增可推荐商品：本试验不授予推荐资格。

初始准备报告 `artifacts/domestic-pilot/report.json` 的 attempted=0 仅代表准备阶段。真实结果保存在 `artifacts/domestic-pilot/live-2026-10-04/`：18次请求、5个条码匹配、4个有有效身份资料、3个存在提议补齐字段、0个已核实标签补齐、0个新增可推荐商品。供应商回报扣费单位合计5。程序测试覆盖只读数据、条码错配、规格差异、字段未验证状态、无凭据不调用、鉴权失败停批、敏感异常不输出、未公开占位符过滤及HTTP图片线索计数。

本轮按每类6个选取，共11个身份缺口样本、7个对照，串行间隔1.2秒，无自动重试。修正占位符识别后仅离线重算已保存响应，未重复请求。报告中的 latency_ms 来自离线重算，不代表实际接口耗时。
